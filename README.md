# Скрыть ввод игроков — мод для AI Roguelite

Прячет из игрового лога то, что написали игроки, но **продолжает отправлять это ИИ игры**.
Нужен для совместной игры: когда заранее видишь, что написал напарник, пропадает весь интерес.

Было:

```
Сэр Алдрик: тихо подкрадываюсь к сундуку и вскрываю замок отмычкой
Мира: говорит с Торговцем Ульфом: «сколько за этот клинок?»
```

Стало:

```
Сэр Алдрик совершает действие
Мира с кем-то говорит
```

ИИ при этом получает полный текст без изменений, история сценария тоже сохраняется целиком.

## Установка

Распаковать архив `HidePlayerInput-<версия>.zip` в папку игры — туда, где лежит `AI Roguelite.exe`:

```
D:\Steam\steamapps\common\AI Roguelike
```

Внутри архива уже всё, что нужно: `winhttp.dll`, `doorstop_config.ini`, папка `BepInEx` с модом.
Больше ничего делать не надо, игра сама его подхватит при запуске.

Проверить, что мод встал, можно в файле `BepInEx\LogOutput.log` — там должны быть строчки:

```
[Info   :   BepInEx] Loading [Скрыть ввод игроков 1.2.0]
[Info   :Скрыть ввод игроков] Патч на MakePlayerInputInfoTxt поставлен.
[Info   :Скрыть ввод игроков] Патч на правку кликом поставлен.
[Info   :Скрыть ввод игроков] Патч на подсказку при наведении поставлен.
```

Удалить мод: убрать `BepInEx\plugins\HidePlayerInput.dll`. Убрать совсем всё:
удалить `winhttp.dll`, `doorstop_config.ini`, `.doorstop_version` и папку `BepInEx`.

## Важно про мультиплеер

Текст в логе каждый игрок рисует **у себя на компьютере**: хост присылает только ссылки на записи,
а сам текст клиент достаёт из своих данных (`MpGameSync.cs` синхронизирует записи лога,
`GameLogViewObj.UpdateGraphics` потом сам подставляет текст).

Поэтому **мод нужен обоим игрокам**. Если он стоит только у хоста — хост чужих ходов не увидит,
а напарник увидит всё.

Сапфир-подписка и мастерская для мода не нужны.

## Настройки

Всё настраивается **прямо в игре**: клавиша `F10` открывает окно настроек. Оно работает и в меню,
и во время игры, изменения применяются сразу и сразу же сохраняются в файл.

В окне есть:

- главный выключатель «Мод включён» — выключил, и всё видно как в обычной игре;
- что скрывать: ходы всех игроков или только чужие;
- заглушки: либо одна на всё, либо своя под каждый вид действия (список с полями для правки);
- запрет раскрывать строчку щелчком по ней;
- скрывать ли подсказку при наведении на персонажа;
- напоминание, какие клавиши за что отвечают.

Чтобы про клавишу `F10` не пришлось нигде читать, при запуске игры мод сам пишет про неё
в левом верхнем углу — первые 12 секунд. Это отключается (`ПодсказкаПриЗапуске`).

Тем же самым можно управлять из файла `BepInEx\config\shantargon.airoguelite.hideplayerinput.cfg`
(появится после первого запуска игры). Все подписи в нём на русском.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `Включено` | `true` | Главный выключатель. `false` — мод стоит на месте, но ничего не прячет. |
| `Режим` | `все` | `все` — скрывать ввод всех игроков, включая свой. `чужие` — скрывать только чужой ввод, свой виден. `выкл` — ничего не скрывать. |
| `Формат` | `{имя} совершает действие` | Что показывать вместо написанного. `{имя}` подставляется само. Можно `{имя}: …`, можно `{имя} что-то задумал`, можно просто `…` — тогда имени не будет вообще. |
| `ЗакрыватьПодсказку` | `true` | Если навести мышь на персонажа, игра показывает в подсказке, какое действие он уже выбрал (`ItemTooltip.cs:716`). С этой настройкой там тоже будет заглушка. |
| `ЗапрещатьПравкуКликом` | `true` | В игре по строчке лога можно щёлкнуть и начать её править — поле правки показывает настоящий текст. С этой настройкой по скрытым строчкам щёлкать нельзя. |
| `КлавишаПоказать` | `F9` | Показать / снова скрыть уже написанное. Перерисовывает лог целиком. |
| `КлавишаНастроек` | `F10` | Открыть окно настроек в игре. |
| `ПодсказкаПриЗапуске` | `true` | Писать в углу экрана при запуске, что настройки открываются по `F10`. |
| `ПодсказкаСекунд` | `12` | Сколько секунд держать эту подсказку. `0` — не показывать вовсе. |
| `ПисатьВЛог` | `false` | Отладка: писать в `LogOutput.log`, что именно было спрятано. Учти, что тогда текст игроков попадёт в файл лога. |
| `СнимокЭкранаПриЗапуске` | `false` | Отладка для разработчика мода: через 14 секунд после запуска само открыть окно настроек и сохранить снимок экрана в папку игры. |

### Заглушки под разные действия

Раздел `[Заглушки]` в файле настроек. `ПоТипуДействия = true` (по умолчанию) — мод сам понимает,
что именно сделал игрок, и подставляет подходящую заглушку. `false` — на всё одна, из `Формат`.

| Вид | По умолчанию | Когда срабатывает |
|---|---|---|
| `Свободное` | `{имя} совершает действие` | игрок написал текст сам |
| `Разговор` | `{имя} с кем-то говорит` | разговор с персонажем |
| `Предмет` | `{имя} использует предмет` | применение предмета, в том числе по персонажу или месту |
| `Умение` | `{имя} применяет умение` | способность |
| `Атака` | `{имя} атакует` | удар голыми руками |
| `Ломает` | `{имя} что-то ломает` | выломать, разбить предмет обстановки |
| `Крафт` | `{имя} что-то создаёт` | крафт и переработка |
| `Обыск` | `{имя} кого-то обыскивает` | обыск тела |
| `Сбор` | `{имя} что-то собирает` | добыча и сбор ресурсов |
| `Взаимодействие` | `{имя} с чем-то взаимодействует` | взаимодействие с объектом |
| `Предложение` | `{имя} что-то предлагает` | отдать предмет персонажу |
| `Побег` | `{имя} пытается убежать` | попытка убежать из боя |
| `Переход` | `{имя} куда-то направляется` | уход в другое место, портал |

Атака оружием считается применением предмета — игра и сама описывает её шаблоном
«использует предмет по персонажу» (`GameplayManager.cs:12242`).

## Как это работает внутри

В игре есть ровно одна функция, которая собирает серую строчку «Имя: что игрок написал»:

```csharp
// GameLogViewObj.cs:288
public static string MakePlayerInputInfoTxt(string actorName, string playerInput)
{
    return Utils.Colorize(((!Utils.IsNullOrEmpty(actorName)) ? (actorName + ": ") : "")
                          + Utils.CapitalizeFirstChar(playerInput), "cccccc");
}
```

Её результат уходит только в текст на экране — `GameLogViewObj.UpdateGraphics` (строка 528)
и `GameplayManager.LogTryStrWCurrentActor` (строка 14961). Больше нигде она не используется.

Промт для ИИ собирается совсем в другом месте и из другой переменной:
`UnifiedPromptBuilder.BuildUnifiedUserPrompt(...)` получает `ActionPrep.TryStr()`, тогда как в лог
идёт `ActionPrep.TryStrForLog()` (`GameplayManager.cs:13073` и `13080`). Поэтому подмена строчки
лога физически не может повлиять на то, что видит ИИ.

Мод ищет функцию по имени через рефлексию. Если игра обновится и что-то переименуют — мод напишет
в лог, что цель не нашлась, и просто ничего не сделает. Игра продолжит работать.

### Какие действия закрыты

Все. Серую строчку с вводом игрока в игре умеют печатать только эти места, и все они проходят
через `MakePlayerInputInfoTxt`:

| Место | Что это |
|---|---|
| `GameplayManager.cs:13074` | единый поток, несколько игроков разом (мультиплеер) |
| `GameplayManager.cs:13081` | единый поток, один игрок |
| `GameplayManager.cs:11574, 11779, 11788, 11874` | `LogTryStrWCurrentActor` — остальные действия |

Тип действия роли не играет: свободное действие, разговор с NPC, крафт, взаимодействие с объектом,
применение способности или предмета — всё это сначала превращается в «строку попытки»
(`ActionPrep.TryStrForLog()`), а печатается уже одной и той же функцией. Указания в скобках при
использовании способностей — часть той же строки (`InteractionLogic.GetPreRollTryStrWithMaybePlayerInst`),
так что они тоже скрываются.

Единственное не закрытое место — `GameplayManager.cs:3427`, где старый (не единый) поток печатает
действие как `[текст]`. В совместной игре этот путь не работает никогда: `IsUnifiedFlow()` возвращает
`true` для любой сетевой игры (`GameplayManager.cs:14833`). Всплыть может только в одиночной игре
со старым режимом ведущего.

### Как мод узнаёт вид действия

Тип действия (`InteracterInfo.InteracterType`: `CONVERSATION`, `USE_ITEM`, `ABILITY`, `CRAFT`...)
известен только на том компьютере, где это действие выбрали. По сети уходит уже готовый текст:
`MpActionQueuedMsg` с типом летит **только хосту** (`MpTurnCoordinator.cs:137`), а остальным
достаётся `MpTurnSeat.tryStr` и текст записи лога — без типа. Значит, у чужого хода тип надо
доставать из самого текста.

Все такие строчки игра собирает из своих же шаблонов перевода: `say-to-char-trystr`,
`use-item-on-char-trystr`, `craft-via-story-trystr` и ещё 34 штуки (`GameplayManager.cs:12014`
и далее). А `LS.GetLocStr` отдаёт шаблон как есть, если не передавать подстановки
(`LS.cs:3326`: `(map == null || map.Count <= 0) ? entry?.Value`).

Поэтому мод просит у игры каждый шаблон, подставив вместо имён предметов и персонажей
метку `\u0001`, и превращает его в выражение для поиска: литеральные куски экранируются,
метки становятся `.+?`. Строчку лога сверяем с этими выражениями, от самых длинных к коротким.
Ни один не совпал — значит, игрок писал текст сам, это свободное действие.

Способ работает на любом языке игры (шаблоны берутся из её же таблицы переводов) и одинаково
у хоста и у клиента. Ошибка распознавания ничем не грозит: вместо текста всё равно подставляется
заглушка, просто она может оказаться не того вида.

### Горячие клавиши: три отдельные ловушки

Первая рабочая версия окна настроек не открывалась по `F10` вообще. Причин оказалось три,
и каждая по отдельности убивала клавиши насмерть.

**1. Объект, созданный в `Awake`, не доживает до игры.** BepInEx запускает плагин до загрузки
первой сцены. Созданный в этот момент `GameObject` Unity выбрасывает при первой же загрузке
сцены — `DontDestroyOnLoad` на него в этот момент ещё не действует. Получалось, что заплатки
(их ставит Harmony, им объект не нужен) работали, а всё остальное — `Update`, корутины, `OnGUI` —
молча не запускалось. Лечится пересозданием объекта на каждой загрузке сцены:

```csharp
SceneManager.sceneLoaded += OnSceneLoaded;
EnsureHost();
```

**2. Игра собрана с новой системой ввода.** В `Player Settings` выбран Input System package,
а при этом старый класс `UnityEngine.Input` не просто пуст — он бросает исключение при любом
обращении:

```
InvalidOperationException: You are trying to read Input using the UnityEngine.Input class,
but you have switched active Input handling to Input System package in Player Settings.
```

Поэтому клавиатуру читает `Keys.cs`: сначала пробует старый способ, а если тот ругается —
переходит на `UnityEngine.InputSystem.Keyboard.current[Key.F10].wasPressedThisFrame`, причём
через рефлексию. Прямая ссылка на `Unity.InputSystem.dll` сломала бы мод на сборке игры
со старым вводом, а так оба варианта работают. Имена клавиш в двух системах различаются
(`LeftControl` -> `LeftCtrl`, `Return` -> `Enter`, `Alpha1` -> `Digit1`, `Keypad1` -> `Numpad1`),
их переводит таблица в том же файле.

**3. `KeyboardShortcut.IsDown()` из BepInEx непригоден.** Он перебирает весь список `KeyCode`,
включая кнопки мыши и геймпада, и требует, чтобы не была нажата ни одна лишняя клавиша.
С подключённым контроллером, у которого «дрожит» ось или залипла кнопка, сочетание
не сработает никогда. Вместо него — `Plugin.Pressed()`, который смотрит только саму клавишу
и её модификаторы.

### Подсказка при наведении

Отдельная утечка, не связанная с логом: если навести мышь на персонажа, игра показывает
зелёным курсивом, какое действие он **уже выбрал**, — ещё до того, как ход сыграет
(`ItemTooltip.cs:716` -> `MpTurnCoordinator.QueuedTryStrForChar`). Мод подменяет и это
(настройка `ЗакрыватьПодсказку`).

### Почему обычным модом (текстовыми файлами) это не сделать

Официальная система модов игры (`ai-roguelite-config\my-mods`) подменяет только текстовые файлы
промтов. А строчка с указаниями игрока собирается так:

```csharp
// InteractionLogic.cs:170-177
return new LS.LocWModded(
    baseTryStrs.locStr + " " + LS.I.GetLocStr("player-inst-w-paren", ("str", playerInst), ...),   // видно в чате
    baseTryStrs.maybeModdedEnStr + " " + SS.I.chatGptPromptsDict["player-inst-w-paren"]...        // уходит ИИ
);
```

Файл мода попадает в `chatGptPromptsDict`, то есть правит **то, что видит ИИ**, а не то, что
видно в чате. Видимый текст берётся из таблицы переводов Unity (`StringTable "MyTable1"`), которая
лежит внутри ассетов игры и файлом не правится. А у свободных действий шаблона вообще нет — там
текст игрока идёт как есть.

## Сборка из исходников

Нужен .NET SDK (проверено на 8.0.303).

```
dotnet build src/HidePlayerInput/HidePlayerInput.csproj -c Release
```

Собранный `HidePlayerInput.dll` автоматически копируется в `BepInEx\plugins` папки игры.
Если игра стоит в другом месте:

```
dotnet build src/HidePlayerInput/HidePlayerInput.csproj -c Release -p:GameDir="путь\к\AI Roguelike"
```

Папка `vendor/` (архив BepInEx и распакованные библиотеки для сборки) в git не хранится,
её восстанавливает `tools/get-bepinex.ps1`.
